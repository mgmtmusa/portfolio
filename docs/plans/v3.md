# v3 dark rebuild: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild Musa Abdullah Walid's portfolio as a dark, Liquid Glass, every-number-footnoted site that passes every gate in section 9 of the brief.

**Architecture:** Static Astro 5 pages with real HTML for every fact (works with no JS). Persistent chrome (status strip, dock, ⌘K) survives Astro view transitions (`ClientRouter`, `transition:persist`). Small, typed, framework-free client modules add the clock, the hero lens, the pane-to-dock scene (GSAP ScrollTrigger), Lenis, the case sheet's view transition, the typeset brief and analytics. Pure logic lives in separate modules covered by Vitest.

**Tech Stack:** Astro 5.18, TypeScript strict, GSAP 3.15.1 + ScrollTrigger, Lenis 1.3.27, `@vercel/analytics` 2, self-hosted variable fonts from `@fontsource-variable` (display face per `DESIGN.md`, Geist, Geist Mono), Playwright 1.65 + axe, Vitest. No React, no three.js (the hero pane bend is an SVG lens; see `docs/v3/LOG.md`).

**Spec:** `docs/MASTER-PROMPT-v3.md` (the brief), `docs/v3/story.md` (copy), `DESIGN.md` and `.impeccable/surfaces/` (direction contract).

## Global Constraints

- Every fact from `src/data/site.ts`; scope notes travel with their numbers; no number more than twice on a page.
- No em dashes anywhere, including titles, meta and JSON-LD. No phone number or street address.
- Banned words and patterns: brief section 5.
- `site.availability`, `site.workRights`, `site.replyTime`, `site.cv` used verbatim.
- Palette: bg `#121110`, raised `#1A1816`, glass fallback `#211F1C`, text `#F3F1EC`, secondary `#A3A19B`, tertiary `#827F7A` (on bg only), hairline `rgb(255 255 255 / .08)`, accent `#D8C69E` (≤1% of any screen). Refinements only as recorded in `DESIGN.md`.
- No functional text under 11px. Mono labels +0.08em.
- Glass: at most 4 visible `backdrop-filter` elements; no backdrop blur on large scrolling surfaces on phones; solid fallbacks under `prefers-reduced-transparency`, `prefers-contrast: more` and no `backdrop-filter` support.
- Motion: expo-out `cubic-bezier(.16, 1, .3, 1)` for entrances; critically damped springs for dock and sheet; reduced motion is a complete version; Lenis off under reduced motion.
- JS requested before `load` ≤ 150 KB gzipped.
- Australian English, first person in page copy, third person in meta and JSON-LD.
- Previews only: `npx vercel@66.6.0 deploy -y`. Never `--prod`, `promote`, a push, or a merge to `main`.

## Review Focus

1. **No JavaScript:** every page shows every fact, the hero shows the CSS pane with no bend, footnotes are reachable as an in-page list, the brief form still opens a `mailto:`. → `tests/e2e/nojs.spec.ts` (Task 11).
2. **Phone at 375×667 in LinkedIn's in-app browser height:** the masthead never overflows, the dock never covers the primary action or the last line of content, the pane never sits over the face. → capture overflow check in `scripts/qa/capture.mjs` and `tests/e2e/layout.spec.ts` (Task 11).
3. **Aim-to-reply-by across weekends, late Friday in Melbourne, and a visitor in another timezone:** the date is two business days on in Melbourne time, never the visitor's. → unit tests (Task 3).
4. **Brief fields with line breaks, ampersands, emoji or 2,000 characters:** the `mailto:` stays valid and the preview never overflows. → unit tests (Task 3) and `contact.spec.ts` (Task 8).
5. **Deep link `/work/evitech/` opened cold, then Close:** goes to `/work/`, focus returns to the Evitech figure, the back button behaves. → `work.spec.ts` (Task 7).

## Motion system

| Moment | Duration | Curve | Reduced motion |
|---|---|---|---|
| Hero load sequence | per `DESIGN.md` (≤ 1400ms total, content visible by default) | expo-out | none, all present |
| Pane → dock | scroll-scrubbed over 60vh | linear scrub, pane eased `power3.out` | pane stays, dock present |
| Figure → sheet | 520ms | view transition, expo-out | 160ms cross-fade |
| Dock open | 360ms | critically damped spring (`linear()`) | instant |
| ⌘K open | 220ms scale .98 → 1 + blur 0 → 14px | expo-out | instant |
| Hover, press | 120 to 160ms | ease-out | same |
| Brief typesetting | per keystroke, 0ms delay | none | same |

**Lifecycle across view transitions** (`gsap-frameworks`): register ScrollTrigger once in `scripts/motion.ts`. On `astro:page-load`, create every scene inside `gsap.context(fn, document.querySelector('main'))`; on `astro:before-swap`, `ctx.revert()` and remove the hero lens. One Lenis instance lives for the whole visit (it is outside the swapped DOM): `lenis.on('scroll', ScrollTrigger.update)`, `gsap.ticker.add((t) => lenis.raf(t * 1000))`, `gsap.ticker.lagSmoothing(0)`, and `lenis.scrollTo(0, { immediate: true })` after each swap. Under reduced motion (or `html[data-motion="reduce"]`), Lenis is never created and `gsap.matchMedia()` skips every scene.

## Budgets

JS before load ≤ 150 KB gz (expected ≈ 50 KB: GSAP + ScrollTrigger + Lenis + own modules). Fonts: three latin woff2 files, display face preloaded. Portrait AVIF/WebP ≤ 80 KB at the largest hero size. LCP < 1.8 s mobile; CLS < 0.02.
